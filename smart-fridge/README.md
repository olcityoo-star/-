# Умный холодильник своими руками

Система, которая делает то же, что дорогие холодильники с камерами: смотрит внутрь
обычной Wi-Fi камерой, распознаёт продукты и показывает их списком в приложении —
что лежит, сколько, когда положили и что скоро испортится.

Никакого вмешательства в сам холодильник не требуется: камера ставится внутрь,
сервис крутится на домашнем сервере, Raspberry Pi или обычном компьютере.

## Что умеет

- Снимает кадр с Wi-Fi камеры по HTTP, MJPEG или RTSP.
- Распознаёт продукты — локальной моделью YOLO или мультимодальной моделью по API.
- Ведёт список содержимого: количество, дата появления, оставшийся срок свежести.
- Показывает ленту событий: «молоко закончилось», «появился йогурт».
- Составляет список покупок из закончившихся базовых продуктов и просрочки.
- Отдаёт последний кадр с рамками распознанных продуктов.
- Позволяет поправить количество руками, если камера чего-то не видит.

Веб-приложение адаптировано под телефон: открывается по адресу сервера, ставится
на домашний экран как обычное приложение.

## Как это устроено

```
Wi-Fi камера ──кадр──> сервис ──> распознавание ──> учёт ──> SQLite
  внутри                                                       │
холодильника                                                   ▼
                                              веб-приложение на телефоне
       ▲
       │ снять сейчас
  датчик двери (ESP8266 + геркон) — необязателен
```

Снимок делается по таймеру, по кнопке в приложении или по сигналу датчика двери.
Кадр прогоняется через распознавание, результат сравнивается с текущим списком,
и разница записывается как события «появилось» / «закончилось».

## Быстрый старт: посмотреть без камеры

Демо-режим рисует синтетическую полку холодильника и «узнаёт» нарисованное, так что
всю систему можно потрогать до покупки железа.

```bash
cd smart-fridge
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000` и нажмите «Сканировать» несколько раз: продукты
появятся в списке, а между сканами сцена меняется — видно, как работает лента событий.

## Железо

### Минимальный комплект

| Что | Зачем | Ориентир по цене |
| --- | --- | --- |
| Wi-Fi камера (у вас уже есть) | снимает полки | — |
| Светодиодная лента 5 В, тёплый белый, 20–30 см | внутри закрытого холодильника темно | 300 ₽ |
| Повербанк или БП 5 В / кабель наружу | питание камеры и подсветки | 500–1500 ₽ |
| Герметичный бокс или пакет с силикагелем | защита от конденсата | 200 ₽ |
| ESP8266/ESP32 + геркон | снимок в момент закрытия двери (необязательно) | 500 ₽ |
| Мини-ПК, Raspberry Pi или домашний сервер | крутит сервис | — |

Если своей камеры нет, самые дешёвые варианты — модуль **ESP32-CAM** (около 600 ₽,
отдаёт кадр по `http://IP/capture`) или **старый смартфон** с приложением IP Webcam.

### Куда ставить камеру

- **Сверху по центру, под потолком камеры холодильника, объективом вниз-вперёд.**
  С этой точки видно все полки; сбоку передние продукты закрывают задние.
- Угол обзора нужен широкий, от 100°. Узкая камера захватит одну полку.
- Дверцу лучше снимать отдельно или вести руками: с потолка её содержимое не видно.
- Держите зону съёмки свободной: продукты, стоящие в два ряда, распознаются плохо.
  Помогает правило «высокое назад, мелкое вперёд».

### Три проблемы, о которые спотыкаются все

1. **Конденсат.** При открытии двери тёплый воздух оседает на холодном объективе, и
   кадр становится молочным. Камеру — в герметичный бокс с пакетиком силикагеля,
   объектив — вплотную к прозрачной стенке. Силикагель менять раз в пару месяцев.
2. **Питание.** Аккумулятор при +4 °C садится за пару дней. Нормальное решение —
   тонкий плоский USB-кабель, выведенный через уплотнитель двери: резинка его
   прижимает, герметичность не страдает. Второй вариант — отверстие в задней стенке
   (только если понимаете, где проходит контур охлаждения; в морозильную камеру
   сверлить нельзя).
3. **Wi-Fi.** Металлический корпус работает как экран, сигнал 2,4 ГГц садится на
   20–30 дБ. Если камера отваливается — выведите антенну наружу через тот же
   уплотнитель или поставьте рядом с холодильником репитер.

### Свет

Внутри закрытого холодильника темно, а лампа загорается только при открытой двери.
Варианты:

- Снимать в момент открытия двери — просто, но в кадре рука и полупустая полка.
- **Своя подсветка на время снимка** — лучший вариант: лента 5 В включается через
  MOSFET на пару секунд, снимок делается при закрытой двери, когда всё видно.
  Готовая прошивка: [`hardware/door_sensor/door_sensor.ino`](hardware/door_sensor/door_sensor.ino).
- ИК-подсветка самой камеры — работает, но кадр чёрно-белый, а цвет для
  распознавания продуктов важен. Как запасной вариант годится.

## Подключение вашей камеры

Сервису нужен адрес, по которому камера отдаёт кадр. Типовые адреса:

| Камера | Адрес |
| --- | --- |
| Hikvision | `http://IP/ISAPI/Streaming/channels/101/picture` |
| Dahua | `http://IP/cgi-bin/snapshot.cgi` |
| Reolink | `http://IP/cgi-bin/api.cgi?cmd=Snap&channel=0&user=ЛОГИН&password=ПАРОЛЬ` |
| ESP32-CAM | `http://IP/capture` |
| Android + IP Webcam | `http://IP:8080/shot.jpg` |
| TP-Link Tapo, Wyze и прочие «облачные» | снимка нет, только RTSP: `rtsp://ЛОГИН:ПАРОЛЬ@IP:554/stream1` |

Проверьте адрес до настройки сервиса:

```bash
curl -u ЛОГИН:ПАРОЛЬ --digest "http://192.168.1.50/cgi-bin/snapshot.cgi" -o test.jpg
```

Если в `test.jpg` картинка — всё готово. Пропишите адрес в `.env`:

```bash
cp .env.example .env
```

```ini
CAMERA_URL=http://192.168.1.50/cgi-bin/snapshot.cgi
CAMERA_USERNAME=admin
CAMERA_PASSWORD=секрет
```

Для RTSP нужен OpenCV: `pip install -r requirements-ml.txt`, затем
`CAMERA_URL=rtsp://admin:секрет@192.168.1.50:554/stream1`.

Если камера умеет сама отправлять снимки на сервер (по движению или расписанию),
направьте её на `POST http://СЕРВЕР:8000/api/scan/upload` — файл в поле `file`.

## Выбор распознавания

| Режим | Что нужно | Что распознаёт | Скорость | Цена |
| --- | --- | --- | --- | --- |
| `demo` | ничего | нарисованную сцену | мгновенно | бесплатно |
| `yolo` | `requirements-ml.txt`, ~2 ГБ на диске | около 12 категорий еды из COCO: яблоко, банан, апельсин, брокколи, морковь, сэндвич, пиццу, бутылку… | 0,3–2 с | бесплатно, работает офлайн |
| `vlm` | ключ к API | практически всё, включая сметану, творог и пельмени, читает надписи на упаковках | 2–6 с | ~0,2–1 ₽ за снимок |

**Рекомендация.** Начните с `vlm`: без обучения и настройки он сразу даёт
осмысленный список продуктов на русском языке. При 20 сканах в день это несколько
рублей в месяц. Если не хотите отправлять кадры наружу — берите `yolo` и дообучите
модель на своих фотографиях, это единственный способ получить приличную точность
локально.

```ini
# вариант с моделью по API (подойдёт любой OpenAI-совместимый сервис,
# в том числе локальные Ollama и llama.cpp)
DETECTOR=vlm
VLM_API_URL=https://api.openai.com/v1
VLM_API_KEY=sk-...
VLM_MODEL=gpt-4o-mini
```

```ini
# полностью локальный вариант
DETECTOR=yolo
DETECTOR_MODEL=yolov8n.pt
```

### Дообучение YOLO на своих продуктах

Готовая `yolov8n.pt` не знает ни сметаны, ни колбасы. Чтобы она заработала
по-настоящему, нужен свой датасет — и это не так долго, как кажется:

1. Пусть сервис поработает неделю: он сложит кадры в `data/snapshots/`.
2. Разметьте 200–300 кадров в [Label Studio](https://labelstud.io) или CVAT.
   Классы берите из своего холодильника, 15–25 штук достаточно.
3. Обучите: `yolo detect train data=fridge.yaml model=yolov8n.pt epochs=100 imgsz=640`.
4. Пропишите `DETECTOR_MODEL=/путь/к/best.pt`.

Названия классов можно писать по-русски: сервис сам сопоставит их с каталогом
продуктов, включая падежные формы.

## Автозапуск

```ini
# /etc/systemd/system/fridge.service
[Unit]
Description=Умный холодильник
After=network-online.target

[Service]
WorkingDirectory=/home/pi/smart-fridge
ExecStart=/home/pi/smart-fridge/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
User=pi

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now fridge
```

## Как работает учёт

Распознавание всегда шумит: продукт пропадёт из кадра из-за блика, руки или
неудачной тени. Если верить каждому кадру, список будет мигать. Поэтому изменение
применяется, только когда оно подтвердилось на нескольких кадрах подряд
(`CONFIRMATIONS`, по умолчанию 2).

Срок свежести считается от момента, когда продукт впервые попал в кадр, по таблице
хранения из `app/products.py`. Когда продукта становится больше, срок **не**
продлевается: предполагается, что старая упаковка всё ещё в холодильнике.

Правки руками имеют приоритет: продукт, добавленный кнопкой в приложении, камера
не удалит — он может лежать в дверце или в непросматриваемой зоне. Как только
камера сама его увидит, продукт снова становится обычным.

## API

| Метод | Адрес | Что делает |
| --- | --- | --- |
| `GET` | `/api/status` | состояние камеры, модели, последний кадр с рамками |
| `GET` | `/api/inventory` | содержимое, разбитое по категориям, и список покупок |
| `GET` | `/api/events?limit=50` | лента событий |
| `POST` | `/api/scan` | снять кадр и обновить список |
| `POST` | `/api/scan/upload` | принять кадр, присланный камерой (`multipart`, поле `file`) |
| `POST` | `/api/items/{key}` | задать количество руками: `{"count": 2}` |
| `GET` | `/api/snapshot.jpg` | последний кадр |
| `GET` | `/api/catalog` | справочник продуктов и сроков хранения |

Интеграция с умным домом: Home Assistant может дёргать `/api/inventory` как
REST-сенсор, а `/api/scan` — как кнопку.

## Чего ждать по точности

Честные ожидания важнее красивых обещаний:

- Крупные бутылки, банки, лотки яиц, овощи на виду распознаются уверенно.
- Продукты в глубине второго ряда, в непрозрачных контейнерах и в дверце —
  практически никогда. Это ограничение не модели, а камеры: чего не видно, того нет.
- Точное количество йогуртов в стопке модель почти всегда путает.
- Поэтому в приложении есть кнопки «+» и «−»: система берёт на себя рутину, а
  редкие ошибки правятся за секунду.

Заводские холодильники с камерами работают ровно так же и ошибаются не реже — они
просто не показывают, что именно распознали.
